# Process overview

## What I built

This site explains the theory of special relativity by letting the visitor experience its effects, following a story-like structure. The user gets control of a rocket's speed and observes time dilation, demonstrating different rates of aging and visual changes to show the character's gap widen. Upon moving to the reunion stage, the side by side reveal shows the difference in aging, with the following section explaining the cause.

## The moments that mattered

`PLAN.md` - a shell of the project (the story and deliverables), not the complex details, was created. I did this so I would have something to reference lightly (if I needed to reference part of the site), or work deeply when focusing on a deliverable. As `CLAUDE.md` loads into every session, I split the two: constraints and test rules stayed in `CLAUDE.md`, project shell and step-by-step deliverables stayed in `PLAN.md`, so I wasn't burning context re-reading details on turns that didn't need to know all the deliverables (examples can be seen in the starting commits of: [`b8de38f`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-BilalM004/commit/b8de38fe5d7451dec3a71ca74c66c98ffbe48e0d), [`82aea9c`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-BilalM004/commit/82aea9c9774e60b9454a773ecd8877ce5a20d373) - `CLAUDE.md` and `PLAN.md` were updated throughout the project). A drawback surfaced later - originally I was going for multiple scenes in the animation, but then later, I changed this to a single flight of the rocket, and needed to remember to update `PLAN.md` to reflect this ([`96cf7da`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-BilalM004/commit/96cf7da59d8e9f6ef21f4949ee86829b4b7be0ec)). Though this structure was kept due to how I work, this event made me realise the tradeoffs - even when I got Claude to update `PLAN.md` to reflect changes discussed, I still needed to remember to update (and review) it - requiring more maintenance, as the agent doesn't automatically read `PLAN.md`.

After going through the narrative once, restarting the story caused the animation to lose its canvas (not display). I had hit animation issues earlier too, and found myself burning tokens making Claude aware of them each time. Rather than continuing to catch restart bugs manually each time, I decided to add a test into the harness, so if future animation work reintroduced the problem, the test suite would flag it before I spent tokens having Claude diagnose it again. I began by mapping out the space/behaviours that triggered the bug, by experimenting with the site. Finding it only occurred after a full initial run - I notified Claude to find the underlying issue, and then form a test for it, so if animation related work was done, a deterministic test could check it behaved as expected ([`15826f8`](https://github.com/comp4020-agentic-coding-studio/comp4020-ass1-BilalM004/commit/15826f8f98ba567a460397da51fbd1246abd9491)), which it verified by intentionally causing animation errors.

Code generation being cheap, I implemented/scrapped ideas with minimal cost. During the animation sequence, I discussed with Claude the textures to use on the planets and the sun, and I needed to decide between pixel-art, or using real imagery. Instead of committing to one, and then deciding to switch later down the line, taking up additional time and budget, I asked Claude to generate a side by side comparison of visuals for both (without animations keep it cheap on tokens). Claude returned a HTML file, to help me visualize better ([here](docs/texture-comparison.html)). The HTML file was cheap and I could clearly visualize the choices I had. The comparison gave me a visual basis for the decision rather than guesswork, giving me more control over the output.
